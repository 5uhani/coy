# Coy Discover

A swipe-based **Discover** tab for Coy, built as a standalone app.
Swipe right to like, left to pass. When two people have liked each other you get an **It’s a match!** moment, and nothing about one-sided likes is ever revealed.

- **Frontend:** React 18 + Vite (mobile-first, plain CSS, no UI library)
- **Backend:** Node.js + Express
- **Storage:** SQLite via Node’s built-in `node:sqlite` (no native modules to compile)

## Features

- Bottom tab bar with a blank **Home** placeholder and the **Discover** tab
- 36 seeded profiles (name, age, photo, bio, city/college, interests). 12 of them have **already liked you**, so matches are easy to demo
- One card at a time: drag/swipe on touch or mouse, **Like / Pass** buttons, and ← / → arrow keys
- Card tilt, **Like / Pass** stamps that fade in as you drag, fly-out animation, snap-back on short drags, next card waits underneath
- A swiped profile never returns, including after reloads and server restarts
- Mutual-match screen, plus a **Matches** view (the toggle at the top of Discover)
- Empty state when there is nobody left, and a retry state if the server is unreachable
- Placeholder portraits are generated by the server as SVGs, so photos work offline

## Privacy: how “never reveal who liked you” is enforced

- Incoming likes live in a private `incoming_likes` table. Only `DiscoverService.swipe()` reads it, to decide whether *your* like completes a mutual match.
- Profiles leave the service through a single `toPublic()` mapper with a fixed field list. There is no “liked you” field to forget to strip.
- `GET /feed` never reads `incoming_likes`, and feed order is fixed per profile, not based on who liked you.
- `POST /swipe` returns exactly `{ "matched": false }` for every non-match: same body for a like, a pass, and for passing someone who liked you.
- The request logger records method, path and status only, never bodies or responses.
- The client holds only the feed and confirmed matches, so there is nothing to leak in frontend state.

## Prerequisites

- **Node.js 22.5 or newer** (needed for the built-in `node:sqlite`; the npm scripts already pass the flag older 22.x versions need) and npm 10+

## Install

```bash
git clone <your-repo-url> coy-discover
cd coy-discover
npm run setup      # installs server/ and client/ dependencies
```

## Run (development)

Use two terminals:

```bash
# terminal 1: API on http://localhost:4000
npm run dev:server

# terminal 2: app on http://localhost:5173
npm run dev:client
```

Open http://localhost:5173. On first start the server creates `server/data/coy.db` and seeds the profiles automatically.

### Single-process production run

```bash
npm run build      # builds client/dist
npm start          # Express serves the API and the built app on http://localhost:4000
```

### Environment variables (all optional)

| Variable | Default | Used by | Purpose |
| --- | --- | --- | --- |
| `PORT` | `4000` | server | API port |
| `DB_PATH` | `server/data/coy.db` | server | SQLite file location |
| `STATIC_DIR` | `client/dist` | server | Built client to serve |
| `API_URL` | `http://localhost:4000` | client (dev) | Where Vite proxies `/api` |

### Reset the demo

```bash
npm run seed       # wipes swipes and matches, reseeds all profiles
```

## Demo instructions

1. Open the app. You land on **Discover**. The first card is someone who already liked you.
2. Drag the card right (or press **♥** / →) to like it. You should see the **It’s a match!** screen.
3. Drag left (or press **✕** / ←) to pass. The card flies off and the next one comes in.
4. Tap **Matches** at the top to see your mutual matches.
5. Reload the page, or restart the server: swiped profiles do not come back and matches remain.
6. Keep swiping until the **You’ve seen everyone for now** empty state appears.
7. Open **Home**: it is intentionally blank.

Passing someone who liked you, or liking someone who didn’t, never shows any hint of who liked you.

## API

Routes are served at `/…` and also under `/api/…` (used by the dev proxy). All bodies are JSON.

### `GET /feed`
Profiles you haven’t swiped on, in a fixed order.
```json
{ "count": 35, "profiles": [ { "id": 1, "name": "Ananya", "age": 21, "photoUrl": "/api/photos/1.svg", "bio": "…", "location": "IIT Delhi", "interests": ["Street food"] } ] }
```

### `POST /swipe`
Body: `{ "profileId": 1, "action": "like" | "pass" }`

| Status | When | Body |
| --- | --- | --- |
| `201` | Swipe saved, not a match | `{ "matched": false }` |
| `201` | Swipe saved, mutual match | `{ "matched": true, "match": { …profile, "matchedAt": "ISO date" } }` |
| `400` | Invalid `profileId` or `action`, or malformed JSON | `{ "error": "…" }` |
| `404` | Unknown profile | `{ "error": "Profile not found" }` |
| `409` | Already swiped on this profile | `{ "error": "…" }` |

### `GET /matches`
Mutual matches only, newest first: `{ "count": 1, "matches": [ { …profile, "matchedAt": "…" } ] }`

### Also
`GET /me` (the logged-in user), `GET /photos/:id.svg` (placeholder portraits), `GET /health`.

## Tests

```bash
npm test
```

Covers: seed data shape (30+ profiles), like and pass removing profiles from the feed, matching only when both sides like, one-sided likes never revealed (field whitelist and identical responses), duplicate swipes (409, no duplicate matches), validation (400/404), empty feed, and persistence after reopening the database file (simulated restart). HTTP-level tests of the Express layer run automatically once `npm run setup` has installed Express.

## Project structure

```
server/
  src/
    index.js            entry: open DB, seed if empty, listen
    app.js              Express app, error handling, static serving
    routes/             route table
    controllers/        HTTP <-> service translation
    services/           matching + privacy logic (framework-free)
    db/                 schema, connection, seed script + data
    lib/                errors, SVG avatar generator
  tests/                node:test suites
client/
  src/
    api/                fetch wrapper
    hooks/              useDiscover (state), useSwipeGesture (drag)
    components/         SwipeCard, SwipeDeck, MatchOverlay, EmptyState, …
    pages/              HomePage (blank), DiscoverPage
    styles/index.css
```
